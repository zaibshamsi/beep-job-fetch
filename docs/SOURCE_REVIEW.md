# Source Review: India fresher / internship sites

Review date: **2026-11-18**. Reviewer: the `indiasites` adapter task. This is evidence for the project reviewers: for every site we considered, what robots.txt said, which Terms page we read, the clause that decided it, and what was built.

Method for each site: (1) fetched `https://<host>/robots.txt` with our honest `BeepJobFetchBot` User-Agent; (2) read the Terms of Use / User Agreement (static fetch, or a one-off headless-browser read when the page is rendered by JavaScript); (3) looked for a public API, RSS feed or sitemap meant for reuse; (4) decided. We never logged in, never spoofed a browser User-Agent, never tried to get around a block or a WAF. Where a site blocked us, that is recorded as "unreachable" and the site was not built.

Decision values: `allowed`, `allowed_with_limits`, `forbidden`, `unclear`. Only the first two are built. `unclear` is treated as "do not build" until the owner decides.

## Sitemaps and JSON-LD `JobPosting`

We looked for sitemaps that lead to `JobPosting` JSON-LD pages. Shine, foundit (`todays-jobs-sitemap.xml`), Cutshort, Instahyre, Freshersworld and Apna all list sitemaps in robots.txt (we did not check which of them embed `JobPosting`), but every one of them is `forbidden` or `unclear` above on ToS grounds, so none was used. JSON-LD is machine-readable by design, but it does not override a Terms clause that bans automated access. Unstop and FreshersVoice offer cleaner JSON APIs, so no JSON-LD parsing was needed.
